# DB 전환 검토

2026-09-30 · 0.13.0 기준 · 연구자의 물음: "데이터들을 DB 에 저장할 필요는 없어?"

## 1. 결론

**지금은 DB 를 두지 않는다.** 뷰어가 하는 일(시점 하나의 산지를 통째로 받아 브라우저에서 거르기)에는 미리 구운
정적 파일이 DB 보다 빠르고 단순하다. 아래 §4 의 일 가운데 하나를 하게 되면 그때 **SQLite 파일 하나**를
파이프라인이 굽는 쪽으로 옮긴다(§5). 서버 DB(PostgreSQL 등)는 이 규모에서 얻을 것이 없다.

## 2. 지금 자료가 어떻게 흐르나

```
sources/*.json ──fetch──▶ data/sources/ ──build──▶ data/derived/ ──▶ /srv/WegenersDream/data (읽기 전용 마운트)
 (주소·SHA-256)            (원본 CSV·zip)            (JSON·WebP·PNG)          └ 뷰어가 /data/… 로 그대로 내준다
```

- **읽기**: 시점을 옮기면 브라우저가 `fossils/<나이>.json` 하나를 통째로 받는다. 퇴적기원·국가·연대 범위·
  모호한 연대 거르기는 모두 브라우저(`map.js`)가 한다. 서버가 조건에 맞춰 골라 줄 일이 없다
- **쓰기**: 사람이 쓰는 것은 명칭 덮어쓰기(`<STATE_DIR>/labels.json`) 하나다. 몇 명이 가끔 한 칸씩 고친다 —
  임시 파일에 쓰고 `os.replace` 로 바꾼다(`viewer/labels.py`)
- **바깥에 묻는 것**: 분류군 찾기·채집지 산출 목록은 브라우저가 PBDB API 에 바로 묻는다(CLAUDE.md
  "PBDB 에 바로 묻는 것"). 서버는 PBDB 를 부르지 않는다
- 뷰어(Django)는 `DATABASES = {}` 다(`settings.py`). 웹 이미지에 numpy 등이 들어가지 않게 파이프라인을 import 하지 않는다

## 4. DB 가 필요해지는 때

| 하고 싶은 것 | 왜 DB 인가 | 지금 |
|---|---|---|
| **분류군 찾기를 서버에서** — PBDB 가 막히거나 느릴 때, 또는 산출(occurrence) 단위로 시대를 가로질러 빠르게 | 산출은 채집지보다 한 자릿수 이상 많다. 이름·계급·산지로 색인한 표가 있어야 빠르다 | 브라우저가 PBDB 에 바로 묻는다. 사내망에서 막히면 GSM 처럼 `viewer/pbdb.py` 중계부터 (CLAUDE.md) |
| **PBDB 판 비교** — "지난 받기보다 늘어난 산지" | 받은 날마다 쌓는 표가 있어야 견줄 수 있다 | PBDB 를 주기적으로 다시 받는 cron 이 TODOs 에 있다. 받기가 쌓이기 시작하면 다시 본다 |
| **시대를 가로지르는 질의** — "이 산지가 오르는 모든 시점과 그때 좌표" | 지금은 109 개 파일에 흩어져 있다 | 팝업은 그 시점의 행만 본다. 요구가 없다 |
| **연구자 편집이 늘 때** — 산지 메모·태그·고친 이력 | 동시 쓰기·이력·되돌리기 | 명칭 덮어쓰기 하나뿐이다 |

넷 다 아직 없다. 하나라도 생기면 이 문서를 다시 연다.

## 5. 전환한다면 — SQLite 를 파이프라인이 굽는다

- **어디에**: `data/derived/wegener.sqlite` — 파이프라인(`build`)이 만들고, 지금 가공물처럼
  `/srv/WegenersDream/data` 에 복사한다. 배포(폴더 복사)·백업(원본과 `state/` 만)·읽기 전용 마운트를 그대로 둔다
- **표**(안):
  - `collection` — 산지 한 곳에 한 행(231k). 지금 좌표·연대·환경·국가·지층·`precise`
  - `collection_frame` — (산지, 시점) 마다 그때 좌표·`rotated`(564k). 시점 파일은 이 표의 한 시점이다
  - `occurrence` — 산출(분류군 이름·계급·산지). 서버 찾기를 할 때만
  - `pbdb_receipt` — 받은 날·SHA-256·행 수. 판 비교를 할 때 받을 때마다 한 행
- **뷰어**: 파이썬 표준 `sqlite3` 로 읽기 전용(`mode=ro`)으로 연다 — 웹 이미지에 새 의존성이 없다. Django ORM·
  마이그레이션은 쓰지 않는다(쓰는 쪽이 파이프라인 하나라서). 시점 파일은 **그대로 둔다** — 밀대는 지금처럼
  정적 파일을 받는 편이 빠르고(021 의 미리 받기), DB 는 §4 의 새 기능이 쓰는 문으로만
- **사람이 쓰는 것**(편집이 늘 때): 읽기 전용 자료 DB 와 섞지 않고 `<STATE_DIR>/` 아래 따로 둔다 — 자료를 다시
  구워도 사람이 쓴 것이 남아야 한다(명칭 덮어쓰기와 같은 까닭)

## 6. 버린 것

- **PostgreSQL·PostGIS** — 공간 질의(범위 안의 산지)는 브라우저가 한 시점 안에서 이미 한다. 서버·계정·백업이
  하나 더 늘어날 뿐이다. 연구소 서버의 다른 앱(GSM 은 SQLite)과도 갈래가 다르다
- **시점 파일을 없애고 API 로만** — 밀대를 옮길 때마다 서버가 JSON 을 만들어야 한다. 지금은 nginx 뒤에서
  파일을 그대로 내주고 브라우저가 캐시한다. 느려질 까닭만 는다
- **Django 모델로 자료 넣기** — 자료는 파이프라인이 통째로 다시 굽는 파생물이다. 행 단위로 고치는 일이 없어
  ORM·마이그레이션을 들일 까닭이 없다
