# 027 — 영어판

2026-09-30 · `feature/english`

## 1. 왜, 무엇을 골랐나

TODOs "영어판". 연구소 밖(공동 연구자·학회)에 보일 때 한국어만으로는 읽을 수 없다.

연구자가 고른 것: **머리말의 `한국어 | English` 단추.** 고른 것은 브라우저에 기억하고(`wegener.lang`) 주소에도
`&lang=en` 으로 남겨 링크로 나눌 수 있다. 처음 오는 사람은 한국어(브라우저 언어를 따라 자동으로 바꾸지 않는다).

## 2. 어떻게

- **문구는 `i18n.js` 한 곳** — JS 가 만드는 문구는 `[한국어, 영어]` 쌍(`tr(key, 값)`, `{이름}` 자리), 템플릿 문구는
  템플릿이 한국어 원문이고 영어만 사전(`DOM_EN`)에 둔다. 템플릿은 `data-i18n`(글자)·`data-i18n-html`(굵은 글씨가
  든 문장)·`data-i18n-attr`(placeholder·title·aria-label)로 표시한다. map.js 에서는 `tr` 로 받는다 — `t` 는 이 파일에서
  지역 이름(환경 용어 등)으로 흔히 써서 가려진다
- **자료의 이름은 index.json 의 `en` 칸** — 층서 단위(ICS 영문명), 퇴적 환경 대분류·무리, 국가. 환경 용어는 PBDB 원
  용어가 곧 영어 이름이다. 받자마자 `ko` 칸을 영어로 바꿔 끼운다(`localizeIndex`) — 이름을 쓰는 곳(칩·머리말·환경
  나무·팝업·범례·국가 목록)을 하나하나 고치지 않아도 된다. 국가의 한글 이름은 찾기 별칭에 남겨 영어판에서도
  "한국" 으로 찾힌다
- **언어를 바꾸면 페이지를 다시 불러온다** — 화면 곳곳에서 만든 글자를 모두 다시 그리는 것보다 확실하다. 시점·
  투영·가운데 경선은 주소에 남아 그대로다. 찾던 분류군·거르기는 풀린다
- **영어로 열 때 한국어가 번쩍이지 않게** — `<head>` 의 짧은 스크립트가 주소·기억을 보고 `<html>` 에
  `i18n-pending lang-en` 을 붙여 본문을 가리고, 문구를 바꾼 뒤 map.js 가 벗긴다
- **명칭 고치기는 영어판에서 숨는다** — 고치는 것이 한국어 이름이다(`labels.json`). 덮어쓰기 표도 읽지 않는다
- 계급 이름: 영어판은 PBDB 계급 이름 그대로(`genus` …). `taxa/auto` 의 숫자 계급만 이름으로 바꾼다
- PBDB 출처 인용문의 한국어 한 문장("채집지마다 원 문헌이 …")을 영어로 바꿨다(`sources/pbdb.json`) — 다른 출처의
  인용문이 모두 영어다. 한국어판에서도 영어 인용문으로 보인다. index.json 을 다시 만들어야 한다(`build --no-relief`)

## 3. 확인

헤드리스 크롬, 영어판: 화면 글자 전체에서 한글을 찾아 "한국어" 단추만 남는 것을 봤다(인용문 고치기 전에는
PBDB 인용문 한 줄). 팝업·국가 고르기(한글로 찾기)·분류군 찾기(후보·산출 시대·같은 시대 다른 산지·차례로 보기)·
한국어로 돌아가기. 사내망의 헤드리스 크롬은 PBDB 인증서를 믿지 않아 `--ignore-certificate-errors` 로 쟀다.

## 4. 버린 것

- **Django i18n(gettext)** — 문구 대부분이 map.js 가 만든다. 서버 번역으로는 절반만 된다
- **다시 불러오지 않고 바꾸기** — 층서 칩·환경 나무·팝업·범례·안내문을 모두 다시 그리는 길을 새로 짜야 한다.
  바꾸는 일이 드물어 다시 불러오기로 충분하다
- **브라우저 언어로 처음부터 영어** — 연구실 사람이 영어 브라우저를 쓰면 영어로 떨어진다. 단추 하나로 충분하다
- 명칭 고치기의 영어 이름 — 영어 이름은 ICS·PBDB 의 것이라 고칠 까닭이 적다
