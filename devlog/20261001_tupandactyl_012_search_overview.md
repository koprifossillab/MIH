# tupandactyl 012 — 찾기의 종합 보기, 지도 옮기는 폭, 팝업 자리, 암상

2026-10-01 · `feature/search-overview`

## 1. 찾기의 종합 보기

연구자: "분류군과 국가를 검색하면 먼저 0 Ma 지도를 기반으로 한 종합 산출기록 포인트들을 띄워 줘. 분류군을 검색하면 그 분류군이 산출되는
영역이 나오도록 지도를 옮기거나 클로즈업".

- **오늘날 자리로 그린다** — 모든 시대의 산지를 한 지도에 모으려면 한 시점의 고좌표로는 안 된다(시대마다 판이 다르다). 0 Ma 지도에 지금
  좌표를 찍으면 판 모델을 섞지 않는다 — PALEOMAP 의 0 Ma 는 오늘날이다. 그래서 첫 규칙(판 모델 하나)을 어기지 않는다
- **PBDB `colls/list` 에 바로 묻는다** — 우리 산지 파일은 시점마다 나뉘어 있어 모든 시대를 모으려면 109 개를 받아야 한다. `base_name` 은
  하위 분류군을 다 포함하고 `cc` 는 나라. 산지 단위(산출 기록이 아니라)라 한 분류군 수만 건도 가볍다. 한도 10 만 곳, 넘으면 적는다
- **0.25° 칸으로 묶는다** — 한국만 482 곳, 미국은 수만 곳이다. 칸의 크기는 산지 수(로그), 색은 칸의 가장 많은 퇴적기원 또는 연대 중간값의
  가운데 값의 기. 퇴적기원 체크는 그대로 먹는다. 모호한 연대·연대 범위 거르개는 시점에 매인 것이라 종합 보기에는 걸지 않는다
- **지도 옮기기** — 분류군이면 산지 수로 무게를 단 위도·경도의 2.5–97.5 % 상자로 당긴다. 최소·최대 상자는 외딴 산지 한 곳 때문에 지구
  전체로 물러난다. 나라는 이미 나라 범위로 옮기니(005) 그대로 둔다
- **점을 누르면 그 칸의 산지 목록** — 처음에는 누르면 확대만 했다. 연구자: "확대만 되고 taxa 나 pbdb 정보가 안 떠". 칸의 산지를
  오래된 것부터 펼침 목록으로(80 곳까지, 넘으면 확대하라고 적는다), 한 곳이면 곧장 펼친다. 펼치면 PBDB 산출 목록을 묻고, 분류군을 찾는
  중이면 같은 산지를 `base_name` 으로 한 번 더 물어 그 분류군에 드는 이름을 굵게 앞에 둔다. 확대는 "이 자리로 확대" 단추로 남겼다.
  고좌표 대신 **지금 좌표**를 적는다 — 종합 보기는 오늘날 자리라서
- 점은 찾기 결과의 점(4.6 px)보다 작지 않게, 짙은 테두리로 — 처음 2.2 px 로는 세계 지도에서 한 곳짜리 칸이 안 보였다(연구자)
- 시점을 옮기면 종합 보기에서 나와 전과 같은 찾기가 된다. 다시 보려면 화석 산지 절의 "◎ 모든 시대 보기"
- 찾기 결과가 뜨며 패널의 절이 늘면 지도 크기가 바뀌고(ResizeObserver → `invalidateSize`) 날던 지도가 멈췄다 — 옮기기를 350 ms 미룬다

## 2. 지도 밖으로 옮기는 폭

"지도 밖으로 움직이는 것의 자유도를 2배" — 위경도 바깥 여백이 위아래 10°·좌우 20° 였던 것을 20°·40° 로. 몰바이데는 원래 가두지 않는다.

## 3. 팝업이 가려 읽히지 않는 것

"포인트 설명이 화면에 가려져서 읽히지 않는 경우가 많아". 둘이 겹쳤다.

- Leaflet 의 autoPan 여백이 0 이라 온도계·찾기 카드(왼쪽 위)와 도구 묶음(오른쪽)이 팝업을 덮었다 → 위 150·왼쪽 24·오른쪽 96 px 여백
- 지도 위쪽 산지는 지도를 더 내릴 수 없어(옮기는 폭의 끝) 팝업이 창 위로 잘렸다 → 그때는 점 **아래로** 편다(꼬리를 뒤집는다). 산출 목록이
  늦게 와서 팝업이 자라면 다시 잰다

## 4. 암상

PBDB 산지의 `lithology1·2` 와 형용(`lithadj`)·굳기(`lithification`)·부 암상(`minor_lithology`). PBDB 원 용어 그대로 둔다 — 한글 풀이는
용어 목록을 연구자와 정한 뒤에(환경 나무처럼). 산지 파일에 넣지 않고 팝업을 열 때 묻는다 — 109 개 파일을 키울 만큼 자주 보는 칸이 아니다.
