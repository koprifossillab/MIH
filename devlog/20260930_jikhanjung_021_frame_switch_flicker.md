# 021 — 시점을 옮길 때 산지 점이 깜박이지 않게

2026-09-30 · `work/20260930-koprifossillab`

## 1. 무엇이 문제였나

연구자: 밀대로 시점을 옮기면 산지 점이 껌벅거린다. 속도를 올려 없앨 수 있을 것 같다.

재 보니 **그리는 속도가 아니라 순서** 탓이었다. `loadFossils` 가 새 시점의 산지 파일을 받기 **전에**
점을 지웠다(`fossilLayer.clearLayers()`). 처음 가 보는 시점이면 받는 동안 지도에 점이 없다.
한 번 가 본 시점은 `getJSON` 캐시에서 곧바로 나와 비지 않는다 — 그래서 "가끔" 깜박였다.

paleoserver 에서 헤드리스 크롬(playwright)으로 쟀다. 망은 20 Mbps·지연 40 ms 로 조였다(사내망·VPN 흉내).
산지 파일은 시점마다 평균 0.7 MB, 가장 큰 것(5 Ma) 2.2 MB 다.

| | 새 점이 뜨기까지 | 점이 빈 화면 프레임 |
|---|---|---|
| 전 — 처음 가 보는 시점 | 130~450 ms | 8~27 |
| 전 — 다시 가 보는 시점 | ~60 ms | 0 |
| 후 — 한 칸씩(0.5 초 간격) | ~66 ms(잰 하한) | 0 |
| 후 — 쉬지 않고 연달아 | 60~350 ms | 0 |

점을 그리는 일(`drawFossils`, 많게는 수천 개) 자체는 5~25 ms 로 한 프레임 안팎이다. 여기를 빠르게 하는
것(점을 한 캔버스에 직접 그리기 등)은 깜박임과 상관이 없어 하지 않았다.

## 2. 무엇을 바꿨나

- **점은 새 자료가 올 때까지 둔다.** 새 자료가 오면 한 번에 지우고 그린다. 받기에 실패하면 그 시점에
  머물러 있을 때만 지운다 — 옛 시점의 점이 남아 다른 시점인 체하지 않게
- **`state.payload` 는 전처럼 곧바로 비운다.** 분류군 찾기가 이것을 "이 시점의 좌표" 로 믿고 찾은 산지를
  옮긴다(017). 옛 시점의 것을 남기면 받는 사이에 찾기 결과가 옛 좌표로 그려질 수 있다. 화면의 점과
  자료를 떼어 놓은 것이 이 고침의 요점이다
- **옆 시점(±1)의 산지 파일을 미리 받는다.** 배경 그림은 이미 그렇게 하고 있었다. 받은 것은 `getJSON`
  캐시에 남아 밀대를 한 칸 옮기면 곧바로 나온다
- **해안선도 같은 꼴로.** 먼저 지우고 받던 것을, 받은 뒤 바꾸도록. 해안선이 없는 시점만 곧바로 지운다

## 3. 버린 것

- **캔버스 한 장에 점을 직접 그리기**(Leaflet 표지 수천 개 대신) — 빠르지만 눌림 판정·세모(016)·팝업을
  다시 짜야 한다. 잰 값으로는 필요 없다
- **모든 시점을 처음에 받기** — 109 개 합쳐 70 MB 남짓이다. 옆 시점만으로 한 칸씩 넘기기는 충분하다
- 국경·기온 층은 손대지 않았다. 켜 둘 때만 그리고, 이번에 깜박인다는 말은 산지 점이었다
