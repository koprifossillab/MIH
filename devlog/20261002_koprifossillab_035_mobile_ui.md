# koprifossillab 035 — 휴대폰 화면

2026-10-02 · `feature/mobile-ui`

바깥 사이트(GitHub Pages)를 켜자 연구자가 휴대폰으로 열어 보고 "창 가독성이 다 너무 낮다" 고 했다.

## 1. 글씨가 작았던 까닭 — 페이지가 창보다 넓었다

390 px 창(휴대폰)에서 재 보니 `innerWidth` 가 **495** 였다. 찾기 카드의 처음 자리를 "온도계 오른쪽"(tupandactyl 007)으로 잡으면서
카드가 지도 칸 오른쪽 밖으로 삐졌고, 휴대폰 브라우저는 레이아웃 폭을 그만큼 늘린 뒤 화면 전체를 그 폭에 맞춰 줄인다 — 모든 글씨가
0.8 배 남짓으로 보였다. 760 px 아래의 옛 규칙(026)은 패널을 지도 밑에 쌓는 것뿐이라 이것을 막지 못했다.

그래서 첫째는 **페이지가 창 폭을 넘지 않는 것**이다 — 좁은 창에서 찾기 카드는 지도 위쪽에 가로로 붙이고(끌지 않는다),
`html, body` 는 넘침을 숨긴다.

## 2. 무엇을 바꿨나 — 760 px 아래만

넓은 창은 그대로다(1400 px 에서 찍어 대조했다). 모두 `map.css` 끝의 한 `@media` 묶음과 map.js 몇 줄이다.

- **머리말 두 줄** — 엠블럼·제목·투영·설정이 한 줄, 지금 시점(나이와 층서 칸)이 둘째 줄이고 길면 옆으로 민다. 판 번호·부제는 뺐다(설정 창에 있다).
  전에는 다섯 줄로 화면의 30 % 를 먹었다. 360 px 아래는 제목·투영 글씨를 한 번 더 줄인다
- **지도가 남은 높이를 다 쓴다** — 패널은 **밑에서 올라오는 판**이다(화면의 46 %). 지도 위에 덮이므로 지도 크기가 바뀌지 않고,
  처음에는 접혀 있다(좁은 창에서 처음 여는 사람에게 지도가 먼저다). 접은 상태는 전처럼 기억한다
- **찾기 카드** — 지도 위쪽 가로. 입력 칸 글씨 16 px(이보다 작으면 iOS 가 칸을 누를 때 화면을 확대한다). 카드 높이를 재어 온도계·도구 묶음을
  그 밑으로 내린다(`--find-h`). 찾기 칸을 누르면 판을 내린다 — 후보 목록이 판에 가렸다
- **누르기 좋게** — 패널·설정 창의 글씨와 칸을 키웠다(층서 칩 14 px, 체크 18 px, 펼침 단추 28 px). 설정·분석 창은 창 폭을 거의 채운다
- 온도계·축척은 `zoom` 으로 줄이고, 팝업은 창 폭 안으로 가둔다

## 3. 버린 것

- **휴대폰용 화면을 따로 두기**(템플릿·스크립트 한 벌 더) — 기능이 모두 같고 문구도 i18n 한 곳이라, 같은 DOM 에 CSS 만 달리하는 편이
  기능이 늘 때 따로 놀지 않는다
- **판을 끌어 높이를 고르기** — 지도 끌기와 판 끌기가 손가락 하나에서 부딪힌다. 막대를 눌러 열고 닫기만 한다
- **가로로 눕힌 휴대폰**(폭 760 px 넘고 높이 400 px 남짓) — 넓은 창 배치가 그대로 나온다. 쓰는 사람이 있으면 그때 높이 기준을 더한다

## 4. 확인

헤드리스 Chromium 의 휴대폰 흉내(390·360 px, 화면 배율 2, 터치)로 첫 화면·판 열기·찾기 후보·설정 창을 찍어 봤다 — 레이아웃 폭이 창 폭과 같다.
분류군 찾기 결과는 그 시각에 서버에서 PBDB 가 응답하지 않아 찍지 못했다(패널 안 같은 절이라 같은 규칙을 받는다). 실제 휴대폰에서 한 번 본다.
