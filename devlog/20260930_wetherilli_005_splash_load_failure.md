# wetherilli 005 — 대기 화면과 읽기 실패 안내

2026-09-30 · `feature/ui-polish`

## 1. 왜

GSM 조사에서 가져온 것(연구자가 고름). 첫 화면은 index.json → 배경 그림(2048 폭 webp) → 산지 JSON 순으로 받는데,
그동안 빈 남색 지도와 비어 있는 패널이 보였다. 더 나쁜 것은 **index.json 을 못 읽을 때** — `console.error` 만 찍고
화면은 빈 채로 남아, 서버가 죽은 것인지 기다리면 되는 것인지 알 수 없었다.

## 2. 무엇을 했나

- 자료가 있을 때(`has_data`)만 템플릿에 **대기 화면** — 이름(영문 굵게, 한국어 작게), 도는 고리, "지도를 불러오는 중…"
- **걷는 때**: 첫 배경 그림이 그려지면(`ReliefOverlay` 가 `load` 를 쏘게 했다) 0.3 초 흐려지며 걷힌다. 배경이
  실패해도(`error`) 걷고, 무엇도 오지 않아도 12 초 뒤에는 걷는다 — 배경이 없어도 점·찾기는 쓸 수 있다
- **index.json 을 못 읽으면** 고리를 멈추고 "자료 목록(index.json)을 읽지 못했다 …" 와 **다시 불러오기** 단추
- 영어로 열 때는 `<head>` 의 스크립트가 i18n.js 가 돌 때까지 `<body>` 를 가린다(027). 대기 화면만은 가리지 않고,
  두 언어 문구를 함께 두어 CSS(`.lang-en`)로 고른다 — i18n.js 가 오기 전에도 맞는 언어로 보인다

## 3. GSM 과 다르게 한 것

- GSM 은 **최소 1.2 초** 보인다(너무 빨리 걷히면 깜빡임으로 보인다, GSM devlog 005). 우리는 최소 시간을 두지 않고
  0.3 초 흐려지기로 깜빡임을 없앴다 — 사내망에서 첫 배경이 0.3 초 안팎이라, 1.2 초를 두면 매번 1 초를 기다리게 된다
- GSM 은 `<head>` 에 인라인 CSS 로 둔다. map.css 도 `<head>` 에서 렌더를 막고 먼저 오므로 우리는 map.css 에 둔다
