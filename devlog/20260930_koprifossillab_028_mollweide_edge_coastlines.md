# 028 — 몰바이데에서 정거원통 테두리 해안선을 지운다

2026-09-30 · `fix/mollweide-edge`

## 1. 무엇이 문제였나

연구자: 몰바이데에서 과거(540 Ma 등)로 가면 해안선이 이상하게 나오는 경우가 많다 — 정거원통 지도 가장자리를
해안선으로 둘러친 것 때문. 몰바이데에서는 지워야 한다.

재 보니 셋이 겹쳐 있었다(500 Ma, 가운데 경선 0°).

1. **테두리 자국** — PaleoCoastlines·국경 다각형을 정거원통 사각형에서 자른 선분이 경도 ±180°(500 Ma 에 위도로
   108°), 위도 ±90°(경도로 360°)를 따라간다. 정거원통에서는 지도 틀과 겹쳐 안 보이지만, 몰바이데에서는 두 점짜리
   선분이 타원 가장자리에서 극으로 가는 **사선**이 된다
2. **+180° 점이 왼쪽 끝으로 넘어감** — 가운데 경선이 0° 일 때 경도가 꼭 +180° 인 점은 wrap 으로 −180°(왼쪽 끝)가
   되어 179° 의 이웃 점과 지도 폭을 가로지르는 **가로선**이 된다. 국경에 많았다(흰 가로선 여러 줄)
3. 025 의 이음매 처리(`seamGeo`)는 가운데 경선이 0° 가 아닐 때만 돌았고, 테두리는 ±180° 에 꼭 붙은 선분만 버렸다

## 2. 어떻게 고쳤나

- **몰바이데이면 가운데 경선이 0° 여도 늘 이음매 처리를 한다.** 정거원통은 손대지 않는다
- **이음매를 넘는 판정을 두 점을 돌린 경도의 차로** — `ra + d ≥ 180` 은 179.987 + 0.013 이 부동소수점으로 180 에
  못 미쳐 넘는 것을 놓쳤다. 이제 `|wrap(p) − wrap(a)| > 180`
- 자료가 날짜변경선에서 건너뛰는 곳(180 → −180, 국경)은 그냥 끊는다
- **테두리 선분을 띠로 잡는다**(`edgeSegment`): 두 끝이 모두 같은 쪽 ±180° 또는 ±90° 의 0.1° 안, 또는 날짜변경선
  1° 안에서 위도로 5° 넘게 곧게 오르내리는 선분. 끝점이 꼭 180° 가 아닌 자국(179.941° → 180°, 18°N → 89.8°S;
  510 Ma 의 −180°, 90°S → −179.657°, 30.8°N)이 있어서다. 날짜변경선 0.1°(약 11 km) 안의 짧은 진짜 선도 버려지지만
  보이지 않는 폭이다

## 3. 확인

map.js 의 `splitLine` 을 Node 에서 그대로 돌려, 해안선·국경 전 시점(109 × 2)에서 투영 뒤 경도로 90° 넘게 가로지르거나
위도로 30° 넘게 곧게 뻗는 선분을 셌다. 가운데 경선 0°·60°·−120°·179.5° 에서 극점 바로 옆(85°~90°)의 남극·러시아
국경 선분만 남는다 — 극 가까이라 짧고 화면에서 보이지 않는다. 500·540 Ma 화면(0°, 60°)에서 사선·가로선이 사라졌다.

## 4. 버린 것

- **정거원통에서도 지우기** — 지도 틀과 겹쳐 보이지 않고, 연구자도 몰바이데만 말했다
- **파이프라인에서 테두리를 지우기** — 가공물은 정거원통 기준이고, 정거원통에서는 테두리가 해안선을 닫아 준다.
  몰바이데의 사정은 뷰어의 몫으로 둔다
